# TerraNews 泰拉新闻

- 作者: 不是现在

## 说明

- 播报时刻是**游戏内时间**的 04:30，触发窗口默认 04:30–05:00
- 每天两行：日报本体一行——读今日月相带出**随月相轮换的货架**；**旅商货架单独成行**。
  沙尘暴、暴风雪、大风、日食、血月各在出现时播一次
- 04:30 触发后先等 `DailyDelaySeconds`（默认 2 现实秒）再**重新检测并发布**：原版旅商的
  货是 `Chest.SetupTravelShop()` 在她刷出前才掷好的，抢在换货前一帧读到的还是昨天那批
- 月相货表是从原版 `Chest.SetupShop` 硬编码摘出来的，对应 **Terraria 1.4.5.8 / TShock 6.2.1.0 / OTAPI 3.3.14**。
  启动时会拿 `Main.versionNumber` 比一次，对不上就在日志里给一行警告，但不会拦播报
- 沙尘暴与暴风雪是同一个原版事件，按地形扫描分开播报，可用 `StormType` 固定
- 每日任务与换任务是同一帧触发的（`Main.mfwh_AnglerQuestSwap`），所以播报的一定是新任务
- 服务器**无玩家在线时世界不推进**，此时不会触发播报
- 每日播报效果：

```
[c/4FC3F7:泰拉日报：满月；渔夫：[i:2466]；染料商：[i:2871][i:2872]；动物学家：[i:4768][i:4769]；油漆工：[i:1481]（非墓地）；服装商：[i:245][i:246]；骷髅商人：[i:284][i:3001][i:3002][i:3003][i:3310]]
[c/4FC3F7:旅商：[i:2451][i:2500][i:3100]...]
```

> 自定义模板时请注意：**含物品图标的行只能用一个颜色标签包住整行**，
> 否则图标会显示成 `[i:2466]` 这样的字符串。原因见下方
> [颜色标签与物品图标不能嵌套](#️-颜色标签与物品图标不能嵌套)。

## 配置
> 配置文件位置：tshock/TerraNews.json
```json5
{
  // 总开关。关闭后插件完全静默，改完需重启服务器
  "Enabled": true,
  // 每项功能单独开关，默认为全开
  "Features": {
    "DailyQuestBoard": true,      // 04:30 的整条每日播报
    "QuestFishIcon": true,        // 任务鱼的可交互图标
    "AnglerStatus": true,         // 渔夫当前状态（仅在自定义模板里用到）
    "MoonPhase": true,            // 今日月相
    "MoonSale": true,             // 随月相轮换的货架
    "Sandstorm": true,            // 沙尘暴 / 暴风雪
    "WindyDay": true,             // 大风天的货架
    "Eclipse": true,              // 日食天的货架
    "BloodMoon": true,            // 血月天的货架
    "TravelingMerchant": true,    // 旅商那一独立行的货架
    "ServerLog": true             // 同时写入 TShock 日志
  },
  "BroadcastHour": 4,             // 每日播报小时（游戏内）
  "BroadcastMinute": 30,          // 每日播报分钟（游戏内）
  "TriggerWindowSeconds": 30,     // 触发窗口，单位是游戏内分钟
  "DailyDelaySeconds": 2,         // 触发到发布的延迟（现实秒）：等原版掷出当天新货架
  "StartupDelaySeconds": 5,       // 插件加载后的静默期
  "StormType": "auto",            // auto | sandstorm | blizzard
  "Diagnostics": false,           // 每秒一行诊断日志
  "DailyLines": [
    "[c/4FC3F7:泰拉日报：{moon}；渔夫：{icon}；{sale}]",
    "[c/4FC3F7:{merchant}]"
  ],
  "SandstormLines": [
    "[c/E0A458:特别报道：沙尘暴]"
  ],
  "BlizzardLines": [
    "[c/E0A458:特别报道：暴风雪]"
  ],
  "WindyLines": [
    "[c/9AD4C8:特别报道：大风特卖，{items}]"
  ],
  "EclipseLines": [
    "[c/B39DDB:特别报道：日食特卖，{items}]"
  ],
  "BloodMoonLines": [
    "[c/8B0000:特别报道：血月特卖，{items}]"
  ]
}
```

### 播报长什么样

每日两行。第一行：`泰拉日报：月相；渔夫：图标；店名：图标图标；……`——NPC 之间用
分号，图标之间不留空格，撑满一行由游戏自动折行。第二行是旅商货架，独立成行：

```
泰拉日报：满月；渔夫：🐟；染料商：🎨🎨；动物学家：🐕🐕；油漆工：🖼（非墓地）；服装商：👕👖；骷髅商人：🪃🍶🔦🦴⚖
旅商：🔮💣📦❄️💰
```

旅商读的是 `Main.travelShop`，也就是原版 `Chest.SetupTravelShop()` 在她刷出之前掷好的
那批货。插件在 04:30 触发后先等 `DailyDelaySeconds` 现实秒再读，尽量拿到的是当天掷出的
新货；她一直没出场时读到的仍是上一次的货架。
没有货（`travelShop` 全是 0）时这一整行直接不出现，也不会留下悬空的 `旅商：` 标签。

一次性事件各一行：

```
特别报道：大风特卖，商人：🌬          （实际是 风车 图标）
特别报道：沙尘暴
特别报道：暴风雪
特别报道：日食特卖，蒸汽朋克人：…；机器侠：…
特别报道：血月特卖，商人：…；染料商：…；树妖：…；油漆工：…；服装商：…；蒸汽朋克人：…；机器侠：…
```

**下雨不播报**：原版货架里 `Main.rain` / `Main.sandstorm` 一次都没出现过，
下雨、沙尘暴、暴风雪都不改变任何一家店的货架——沙尘暴和暴风雪只报天气本身。

### 占位符

- 每日：`{icon}` `{angler}` `{id}` `{moon}` `{moon_bonus}` `{sale}` `{merchant}` `{merchant_items}` `{time}`
- 天气：`{storm}` `{time}` `{moon}`
- 大风 / 日食 / 血月：`{items}` `{count}` `{time}` `{moon}`

> 默认模板第二行只放 `{merchant}`：它自带 `旅商：` 前缀，货架为空时整段变空，
> 空行会被丢弃、整行不发。`{merchant_items}` 只给图标、不带店名，店名要模板自己写。
> 两者都归属 `TravelingMerchant` 开关，关掉后用到它们的整行消失。旅商每次到访货都
> 不一样，这里报的是 `Main.travelShop` 当前的 40 格，不是旅商在游戏里打开的原版货架。

> 默认模板只用到其中一部分，想加就自己写进 `DailyLines`。
> `{angler}` 输出纯文本，不能自带颜色标签；`{icon}` 所在行不能嵌套颜色标签（见下）。

> **任务鱼只有 ID**：名称、产地、深度、钓法全部来自原版物品标签 `{icon}` 的悬停提示，
> 插件不再自带鱼的介绍数据。想自定义看板只需改写 `DailyLines`，例如：
> ```json5
> "DailyLines": [
>   "[c/B39DDB:泰拉日报：{moon}；渔夫：{icon}；{sale}]",
>   "[c/7FD4FF:{angler}]",
>   "[c/888888:（游戏时间 {time}）鱼 ID {id}]"
> ]
> ```

### ⚠ 颜色标签与物品图标不能嵌套

这是最容易踩的坑：**含 `{icon}` 或 `{items}` 的行，只能用「一个颜色标签包住整行」**。

原版客户端用一条正则从头扫到尾地解析聊天文本，其中文字部分是非贪婪匹配：

```
\[(?<tag>[a-zA-Z]{1,10})(\/(?<options>[^:]+))?:(?<text>.+?)(?<!\\)\]
```

所以颜色标签只会吞到它后面的**第一个** `]`。写成两段颜色标签时：

```json5
// 错误：图标会变成一串 [i:2453] 字符，不会变成图标
"[c/FFD966:任务鱼] [c/FFFFFF:{icon}]"
```

`[c/FFFFFF:` 的正文字段会把 `[i:2453` 整个当成自己的内容，客户端再也不会把它
渲染成图标。

```json5
// 正确：整行一个颜色标签
"[c/FFD966:任务鱼 {icon}]"
```

这种写法插件会在服务端剥掉标签、改用真正的 RGB 发送，客户端收到的是不含任何标签
的纯文本，图标正常渲染。不含物品标签的行则可以用多段颜色，如
`"[c/B39DDB:今日月相] [c/FFFFFF:{moon}]"`。

> 写到嵌套写法时插件会在 TShock 日志里警告一次，并指出正确写法。

### 沙尘暴与暴风雪

原版的沙尘暴和暴风雪是**同一个 `Sandstorm` 事件**，游戏按玩家所在生物群系决定看起来
是黄沙还是暴雪。它在客户端判定为 `player.ZoneSnow && player.ZoneRain`，但**这两个标志
在专用服务器上不可靠**：`ZoneRain = Main.raining && Y <= worldSurface` 是全局的、准确，
而 `ZoneSnow` 来自客户端算的 `Main.SceneMetrics`，服务器上读到的是过期值。搭配
"一直下雨"（`rain`）种子，`ZoneRain` 恒为真，判据就退化成只看 `ZoneSnow`，容易把
沙尘暴误报成暴风雪。

因此插件不问玩家，改**抽样扫描地表明层**，数沙块(32)与雪块(51)谁多。这个结果只与世界
地形有关，扫描一次后缓存，重启服务器时重新扫描。

> 实测：默认世界与"一直下雨"种子的沙漠地表都约为雪原的 4 倍（沙 8830 / 雪 2378、
> 沙 7516 / 雪 1600），所以 `auto` 的判定结果都是沙尘暴。

沙尘暴与暴风雪无法在同一个世界里两全——同一个事件对沙漠玩家是黄沙、对雪原玩家是暴雪。
如果你要固定用某个名字，或者你的世界地形让 `auto` 判反了，可以直接指定：

| `StormType` | 行为 |
|:--|:--|
| `auto`（默认） | 扫描地表明层，雪多报暴风雪，否则报沙尘暴 |
| `sandstorm` | 一律播报沙尘暴 |
| `blizzard` | 一律播报暴风雪 |

两套模板对应沙与雪两种情况，**风暴只在出现的那一刻播一次**，不跟进强度变化：

| 模板 | 用途 |
|:--|:--|
| `SandstormLines` | 沙尘暴开始 |
| `BlizzardLines` | 暴风雪开始 |

#### 实机验证记录

沙尘暴与暴风雪两侧都已在真实客户端环境下验证通过：起播时的名称、模板与图标都正确。

验证时值得注意的地方：

- **`auto` 依赖世界地形**。需要在雪原为主地表的世界才能判成暴风雪，否则用
  `"StormType": "blizzard"` 强制。启动日志里有一行判定结果，便于确认：
  `[TerraNews] 地形判定：雪块 N 格，沙块 M 格 → 这场按暴风雪播报。`
- **必须先有客户端连上**。专用服务器无玩家在线时世界不推进，自动播报不会发生。
- **控制台复现不出暴风雪场景**。`/worldevent` 的合法事件类型里没有 `blizzard`，
  只能用 `/worldevent sandstorm` 制造，再靠地形决定播报成哪一种。
- **`/worldevent sandstorm` 是开关**，已经在下会把它停掉。反复调用即可反复制造
  「开始播报 → 结束」这条上升沿。

### 月相特售对照表

每日那一行的 `{sale}` 来自一张**硬编码**的对照表，逐条从原版 `Chest.SetupShop`
里挑出来：只抄判断式里带 `Main.moonPhase` 的分支，昼夜、血月、Boss 进度、
「看你背包」这类条件一律不抄。所以运行期只读月相（外加三个世界种子标志），
不必去调原版的货架计算。

表对应 **Terraria 1.4.5.8 / TShock 6.2.1.0 / OTAPI 3.3.14**。启动时拿
`Main.versionNumber` 比一次，对不上就打一行警告，但照常播报。

八个相位各有 5–7 家出货，全部输出：

```
[c/4FC3F7:泰拉日报：满月；渔夫：[i:2466]；染料商：[i:2871][i:2872]；动物学家：[i:4768][i:4769]；油漆工：[i:1481]（非墓地）；服装商：[i:245][i:246]；骷髅商人：[i:284][i:3001][i:3002][i:3003][i:3310]]
[c/4FC3F7:旅商：[i:2451][i:2500][i:3100]...]
[c/4FC3F7:泰拉日报：下弦月；渔夫：[i:2466]；动物学家：[i:4770][i:4771]；机械师：[i:2295]；骷髅商人：[i:3069][i:3001][i:3312][i:5640]]
[c/4FC3F7:旅商：[i:2451][i:2500][i:3100]...]
```

店铺顺序照城镇 NPC 的解锁表排，渔夫提到最前，骷髅商人排在倒数第二（它是 1.4.4
才加的新 NPC，不在那张表里）。旅商不属于这张表，单独占日报的下一行。

#### 物品后面的括号是什么

括号里是**买这件货的前置条件**，跟着图标走：

| 标注 | 含义 | 触发它的字段 |
|:--|:--|:--|
| `（非墓地）` | 不在墓地里才上架 | `!player.ZoneGraveyard` |
| `（remix）` | 重混世界专属 | `Main.remixWorld`，即 Don't Dig Up |
| `（tenth）` | 十周年世界专属 | `Main.tenthAnniversaryWorld` |

腐化 / 猩红 / 普通世界**不做标注**——树妖血月那件毒粉在猩红世界是 `2886`、腐化
世界是 `67`，两者同名，插件按 `WorldGen.crimson` 选物品，但不标世界。

#### 换版本了怎么办

这张表是抄来的，原版改了数值就对不上。启动日志里会有一行

```
[TerraNews] 月相特售对照表来源：Terraria 1.4.5.8 (Protocol 326) / TShock 6.2.1.0 / OTAPI 3.3.14
```

看到版本号和实际不符，就重新对着 `Chest.SetupShop` 核一遍 `MoonSale.cs`。

### 一次性事件

四种事件都在**出现的那一刻**播一次，不跟进强度：

| 事件 | 判据 | 货物 |
|:--|:--|:--|
| 沙尘暴 / 暴风雪 | `Sandstorm.Happening` | **无**（只报天气） |
| 大风 | `Main.dayTime && Main.IsItAHappyWindyDay` | 商人 风车 |
| 日食 | `Main.eclipse` | 蒸汽朋克人、机器侠 |
| 血月 | `Main.bloodMoon` | 商人、染料商、树妖、油漆工、服装商、蒸汽朋克人、机器侠 |

几个容易搞混的地方：

- **下雨不播报**。原版货架里 `Main.rain` 和 `Main.sandstorm` 一次都没出现过，
  雨、沙尘暴、暴风雪都不改变任何一家店的货架。
- **大风和暴风雪无关**。`Main.IsItAHappyWindyDay` 是每天黎明单独掷出来的随机布尔，
  和天气系统没有任何耦合，所以大风那一行和风暴那两行永远不会同时发。
- **大风只在白天算**。原版风车的条件带 `Main.dayTime`，夜里播报就是假消息。
- **沙尘暴不含下雨**。`Sandstorm.StartSandstorm()` 只设 `Happening` 和时长，
  从头到尾没碰 `Main.rain`；触发条件是风速 ≥ 0.6 加随机掷骰。两者互相独立。

### 开关行为

- 关掉某项后，**依赖它的整行会消失**，不会留下没有内容的标签
- 关掉 `TravelingMerchant` 时旅商那一整行不出现，默认模板其他行照播
- 默认模板不使用 `{angler}` `{moon_bonus}`，所以默认配置下 `AnglerStatus` 不影响输出，
  改写 `DailyLines` 后才会生效
- 关掉 `MoonSale`、`QuestFishIcon` 时对应的段直接消失——拼好的行会按 `；` 切成段，
  把只剩店名没有货的残段和空段丢掉再接上，所以不会留下悬空的分号。
  行内还留着颜色标签的自定义写法则整行跳过，不做这个清理

## 更新日志

### v1.0.1

- 旅商从日报本体行拆出，**单独成行**：`DailyLines` 默认改为两行，逐字未改过默认模板的
  存量配置会自动迁移到新默认，改过字的保持原样
- 新增 `DailyDelaySeconds`（默认 2 现实秒）：04:30 触发后先等一小会，再重新检测世界
  状态并发布——旅商的货是当天才掷好的，抢在换货前一帧读到的还是昨天那批；设为 `0`

### v1.0.0

- 每天游戏内 04:30 播报一行：今日月相、渔夫任务鱼、各家随月相轮换的货架，末尾接旅商货架
